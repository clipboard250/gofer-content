Internal SOP · Phase 1

AI VISIBILITY:
SCHEMA CLEANUP.The reusable playbook.

This is the exact sequence Gofer Content runs on every client site to make AI tools (ChatGPT, Perplexity, Google AI Overviews) actually find and cite them. Phase 1 of ongoing AI visibility work. Reddit and Wikipedia strategy comes after this.

Built from the Living Spaces Gardening build · April 2026

What this SOP does

Turns any client site into something AI can actually cite. Takes roughly 60-90 minutes per site. Works immediately. No waiting weeks for results.

Before you start

Gather this first.

Before touching any code, get these from the client. Missing any of this and the SOP won't work properly.

Intake checklist

01 · Business basics

Name, address, phone, email, founding year, all service areas

02 · Credentials

Every certification with years. If dates are fuzzy, get clarification BEFORE coding. If you can't verify, use vague wording ("experienced" not "since 2014")

03 · Google Business

Admin access. Request a Google Takeout export of reviews. Waiting saves hours of manual copy-paste

04 · Social profiles

Every URL the business owns: Instagram, Facebook, LinkedIn, industry directories, trade associations

05 · Press / Features

Full URLs of any articles, podcasts, magazine features. Date published. This is the biggest AI trust signal most sites ignore

06 · Service list

Every service as they describe it. Use their words, not yours

The fixes · in this order

Four fixes. Every time.

Work top to bottom. Do not skip ahead. Each fix builds on the previous.

```
Fix 01

Credential language audit

Why: Conflicting dates across a site destroy E-E-A-T score. AI cross-references credentials and when it finds "since 2014" on one page and "since 2017" on another, it lowers confidence in the whole site.

What to do

  • Search every file for credential mentions (certifications, founding year, "since YYYY")
  • Verify every date with the client. If they can't confirm, use vague language
  • Swap specific years for qualitative descriptors: "experienced," "certified," "credentialed"
  • Update JSON-LD schema to remove unverified dateCreated fields
  • Update visible text (About pages, bios, press kits)
  • Update llms.txt if one exists

Schema pattern

"hasCredential": [
```

{ “@type”: “EducationalOccupationalCredential”, “name”: “Florida Master Naturalist” }
]

Note: Once dates are verified, add dateCreated back in. Never before.

```
Fix 02

sameAs authority links

Why: sameAs tells AI "this entity is the same across these URLs." Every legitimate third-party URL in this array is a trust signal. Most sites only list social media. Add press features, industry directories, and trade associations.

What to do

  • Locate Organization or LocalBusiness schema in homepage JSON-LD
  • Build a sameAs array with every verified URL
  • Include: Google Maps profile, social profiles, industry directories, press features, podcast appearances
  • Do NOT include: aggregator sites, competitor directories, random blogs mentioning the client

Pattern

"sameAs": [
```

“https://www.google.com/maps/place/CLIENT+NAME”,
“https://www.instagram.com/client/”,
“https://www.facebook.com/client”,
“https://www.industry-directory.org/client”,
“https://www.pressfeatureurl.com/article-about-client”
]
```
Fix 03

Press feature NewsArticle schema

Why: A press page with a visible link is nice. Adding NewsArticle schema turns that same link into structured data AI can cite directly. This is the single biggest differentiator between sites AI tools mention and sites they skip.

What to do

  • On the press page, add a second JSON-LD script block for each feature
  • Use @graph to combine WebPage + NewsArticle in one block
  • Reference the business via @id so schema connects
  • Include datePublished, headline, publisher, mentions for the person quoted

Pattern

{
```

“@type”: “NewsArticle”,
“headline”: “ARTICLE TITLE”,
“url”: “https://publication.com/article-url”,
“datePublished”: “2025-11-22”,
“publisher”: {
“@type”: “Organization”,
“name”: “Publication Name”,
“url”: “https://publication.com”
},
“about”: { “@id”: “https://clientsite.com/#business” },
“mentions”: {
“@type”: “Person”,
“name”: “Client Name”,
“jobTitle”: “Founder”,
“worksFor”: { “@id”: “https://clientsite.com/#business” }
}
}
```
Fix 04

Reviews — real ones, with dates

Why: aggregateRating alone (e.g. "5 stars from 10 reviews") is a claim. Individual Review schema with author names and dates is proof. AI weighs proof over claims. Dated reviews across multiple years also prove the business is actively healthy, not a dormant listing.

What to do

  • Request Google Takeout export from client (info@ account for the GBP)
  • Extract reviews.json from the correct location folder
  • Filter: use only reviews with actual text. Star-only reviews still count toward aggregate but can't be cited by AI
  • Match ratingCount to total reviews (including star-only), reviewCount to reviews with text
  • Add datePublished to every individual review
  • Trim review text to the most AI-quotable sentence. Preserve original voice

Pattern

"aggregateRating": {
```

“@type”: “AggregateRating”,
“ratingValue”: “5”,
“bestRating”: “5”,
“ratingCount”: “12”,
“reviewCount”: “11”
},
“review”: [
{
“@type”: “Review”,
“author”: { “@type”: “Person”, “name”: “Reviewer Name” },
“datePublished”: “2026-04-10”,
“reviewRating”: { “@type”: “Rating”, “ratingValue”: “5”, “bestRating”: “5” },
“reviewBody”: “Most quotable sentence from the review.”
}
]

After every build

Don't skip these.

Final checks before moving on

Validate

Run every changed page through validator.schema.org AND Google's Rich Results Test. Both.

Check for duplicates

When replacing JSON-LD blocks, make sure old + new aren't both in the file. Two "review" arrays = broken schema.

Client update email

Send summary of what changed + why. Always include one question that shows you care about accuracy (not laziness).

Test queries

Write 5 specific queries to test in ChatGPT/Perplexity over the next 30 days (e.g. "who does X in Y city"). Track when the client starts appearing.
